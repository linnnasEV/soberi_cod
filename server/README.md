# Сервер платформы

Хранит аккаунты, профили детей, занятия учителей и прогресс. Учебной части —
курсов, заданий, Мастерской — здесь нет: она целиком в браузере, и это
сознательно. Школа со слабым интернетом должна заниматься даже когда сервер
недоступен.

- Python 3.12 и новее, FastAPI, PostgreSQL
- миграции — Alembic, схема описана в [`app/models.py`](app/models.py)
- запуск на сервере — systemd, конфиги в папке [`deploy`](../deploy)

## Устройство

| Файл | Зачем |
|---|---|
| `app/config.py` | настройки из переменных окружения |
| `app/db.py` | подключение к базе, сессия на один запрос |
| `app/models.py` | таблицы и правила целостности |
| `app/security.py` | хеширование паролей, токены сессий, коды занятий |
| `app/schemas.py` | проверка того, что присылает браузер |
| `app/sessions.py` | выдача, продление и отзыв сессий |
| `app/ratelimit.py` | защита от перебора паролей |
| `app/mail.py` | письма: подтверждение адреса, сброс пароля |
| `app/audit.py` | журнал действий с аккаунтами |
| `app/deps.py` | кто сейчас вошёл и что ему можно |
| `app/progress.py` | подсчёт и запись звёзд — в одном месте на всех |
| `app/routers/auth.py` | вход взрослых и детей |
| `app/routers/parent.py` | профили детей у родителя |
| `app/routers/child.py` | прогресс, работы и награды ребёнка |
| `app/main.py` | сборка приложения, защитные заголовки, `/api/health` |
| `alembic/` | миграции базы |

Работа с базой синхронная, обработчики объявляются обычным `def`. Нагрузка
школьная — десятки запросов в минуту даже при полном компьютерном классе, —
а синхронный код проще читать и отлаживать.

## Первая установка на Ubuntu

Проверено на Ubuntu 26.04 с Python 3.14. Дальше считается, что репозиторий
лежит в `/srv/soberikod`. Если он у вас в
другом месте — либо перенесите, либо поправьте путь в двух файлах:
`deploy/soberikod-api.service` и `deploy/deploy.sh`.

### 1. Пакеты

```bash
sudo apt update
sudo apt install -y nginx postgresql python3-venv python3-full rsync certbot python3-certbot-nginx
```

### 2. База

```bash
sudo -u postgres createuser soberikod --pwprompt
sudo -u postgres createdb soberikod --owner=soberikod
```

Пароль, который спросит первая команда, понадобится в файле настроек. Придумайте
длинный — вводить его руками никому не придётся.

### 3. Код и права

```bash
sudo mv /путь/куда/клонировали /srv/soberikod
sudo chown -R root:root /srv/soberikod
sudo chmod -R a+rX /srv/soberikod
sudo useradd --system --shell /usr/sbin/nologin --home-dir /srv/soberikod soberikod
```

Код принадлежит root, а служба работает под `soberikod` и читать его может,
а менять — нет. Это не перестраховка: если в сервере однажды найдут дырку,
через неё нельзя будет подменить ни файлы сайта, ни сам сервер.

### 4. Окружение Python

```bash
sudo python3 -m venv /srv/soberikod/server/.venv
sudo /srv/soberikod/server/.venv/bin/pip install -r /srv/soberikod/server/requirements.txt
```

В Ubuntu установка пакетов Python прямо в систему запрещена
(`externally-managed-environment`) — поэтому всё живёт в `.venv`, и это
правильно: версии проекта не пересекаются с системными.

### 5. Настройки

```bash
sudo install -d -m 755 /etc/soberikod
sudo install -m 600 /dev/null /etc/soberikod/api.env
sudo nano /etc/soberikod/api.env
```

Что вписать — в [`api.env.example`](api.env.example). Файл доступен только root,
а systemd читает его до того, как сбросит права, так что служба настройки
получит, а посторонние — нет. В репозиторий этот файл не попадает никогда:
репозиторий открытый.

### 6. Схема базы

```bash
cd /srv/soberikod/server
sudo SOBERIKOD_DATABASE_URL='postgresql+psycopg://soberikod:ПАРОЛЬ@localhost:5432/soberikod' .venv/bin/alembic upgrade head
```

Проверить, что таблицы совпадают с описанием в `models.py`:

```bash
sudo SOBERIKOD_DATABASE_URL='...' .venv/bin/alembic check
```

### 7. Служба

```bash
sudo cp /srv/soberikod/deploy/soberikod-api.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now soberikod-api
curl -s http://127.0.0.1:8000/api/health
```

Ответ `{"ok":true}` означает, что сервер поднялся и база отвечает. Если нет —
`journalctl -u soberikod-api -n 50`.

### 8. nginx

```bash
sudo install -d -m 755 /etc/nginx/snippets
sudo cp /srv/soberikod/deploy/nginx-headers.conf /etc/nginx/snippets/soberikod-headers.conf
sudo cp /srv/soberikod/deploy/nginx-soberikod.conf /etc/nginx/sites-available/soberikod
sudo ln -s /etc/nginx/sites-available/soberikod /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### 9. Сертификат

A-запись домена должна уже указывать на сервер, иначе проверку пройти нельзя.

```bash
sudo certbot --nginx -d xn--90agcmkuenf.xn--p1ai -d www.xn--90agcmkuenf.xn--p1ai
```

`xn--90agcmkuenf.xn--p1ai` — это соберикод.рф в ASCII-виде. Кириллицу ни nginx,
ни Let's Encrypt не принимают; в адресной строке её подставит сам браузер.

**После этого шага конфиг на сервере отличается от того, что в репозитории:**
certbot дописал в него пути к сертификату и переход с http на https. Копировать
`deploy/nginx-soberikod.conf` поверх живого файла больше нельзя — сайт останется
без TLS. Мелкие правки вносите прямо в `/etc/nginx/sites-available/soberikod`
и повторяйте их в репозитории, чтобы файлы не разъезжались.
Адрес почты, который спросит certbot, нужен для одного письма: «сертификат
истекает, а продлить не удалось». Продление дальше идёт само.

### 10. Сеть и обновления

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo apt install -y unattended-upgrades
```

### 11. Первое обновление сайта

```bash
sudo bash /srv/soberikod/deploy/deploy.sh
```

Дальше все обновления — только этой командой, см. [`../DEPLOY.md`](../DEPLOY.md).

## API: вход взрослых

Всё принимает и отдаёт JSON. Вход хранится в cookie `soberikod_session`:
недоступна из JavaScript, не уходит на чужие сайты, живёт 30 дней со
скользящим продлением — или до закрытия браузера, если при входе отмечен
общий компьютер.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/auth/register` | регистрация учителя или родителя, сразу со входом |
| `POST` | `/api/auth/login` | вход по почте и паролю |
| `POST` | `/api/auth/logout` | выход на этом устройстве |
| `POST` | `/api/auth/logout-all` | завершить входы на всех устройствах |
| `GET` | `/api/auth/me` | кто вошёл |
| `POST` | `/api/auth/password/change` | смена пароля, с текущим паролем |
| `POST` | `/api/auth/password/forgot` | письмо со ссылкой на сброс |
| `POST` | `/api/auth/password/reset` | новый пароль по ссылке из письма |
| `POST` | `/api/auth/verify-email` | подтверждение адреса по ссылке из письма |
| `POST` | `/api/auth/verify-email/resend` | выслать письмо с подтверждением заново |
| `GET` | `/api/auth/session` | кто за компьютером: взрослый, ребёнок или никто |

Роль `admin` через регистрацию получить нельзя — её выдают на сервере.

`/api/auth/session` отвечает всегда, даже когда не вошёл никто, и возвращает
оба поля — `user` и `child`. Этим запросом страница начинает работу: по нему
она решает, показывать кнопку «Войти» или имя со звёздами. Спрашивать по
очереди «а взрослый вошёл?», «а ребёнок?» — лишний повод ошибиться.

Коды из писем приходят в ссылке после решётки: `https://адрес/#reset=КОД`.
То, что идёт после решётки, браузер на сервер не отправляет, поэтому код не
попадает ни в журнал обращений nginx, ни в заголовок Referer при переходе на
чужой сайт. Страница читает его сама и отправляет отдельным запросом.

### Защита от перебора

Главный рубеж — **запирание аккаунта**: после 10 неудачных попыток вход в
конкретный аккаунт закрывается на 15 минут. Счётчик лежит в базе, поэтому
переживает перезапуск сервера и работает одинаково при любом числе рабочих
процессов. От адреса посетителя он не зависит, и это здесь важно.

Второй рубеж — поток запросов: nginx пропускает к `/api/auth/` пачку в 60
запросов и дальше по одному в секунду.

Третий, счёт неудач по адресу посетителя, **на этом сервере не работает, и
так и задумано**. Хостинг держит машину за общим шлюзом: все посетители
приходят с одного внутреннего адреса вроде `192.168.0.1`, настоящий до нас не
доезжает. Считать попытки по такому адресу нельзя — полсотни неудач одного
робота закрыли бы вход всем сразу, а класс из двадцати пяти детей упёрся бы в
предел на первой же перемене. Поэтому `ratelimit.countable_ip` пропускает
счёт, когда адрес внутренний, и по той же причине ограничение в nginx
настроено не «на человека», а «на всех сразу».

Если однажды настоящий адрес посетителя начнёт доходить — заработает и третий
рубеж, менять код не придётся. Проверить, доходит ли, помогает отдельный
журнал: [`deploy/nginx-log.conf`](../deploy/nginx-log.conf).

### Что намеренно сделано именно так

**Неверный пароль и несуществующий адрес отвечают одинаково.** Иначе форму
входа можно превратить в проверялку «кто у вас зарегистрирован».

**Восстановление пароля всегда отвечает «письмо отправлено»** — даже если
такого адреса нет. По той же причине.

**А вот регистрация про занятый адрес говорит прямо.** Это подсказывает
постороннему, что такой человек у нас есть, но молчаливый отказ при
регистрации непонятен живому учителю, и он решит, что сайт сломан. Адреса
взрослых секретом не являются.

**Неподтверждённая почта не мешает войти.** Иначе сбой с письмами запер бы
всех снаружи. Подтверждение нужно, чтобы работало восстановление пароля.

**Смена пароля завершает все остальные входы, сброс — вообще все.** Если
паролем успел воспользоваться чужой, он вылетает немедленно.

## API: дети

### Родитель заводит профили

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/parent/children` | список своих детей со звёздами |
| `GET` | `/api/parent/children/login-free?login=` | свободен ли логин, и чем заменить |
| `POST` | `/api/parent/children` | новый профиль ребёнка |
| `PATCH` | `/api/parent/children/{id}` | имя и картинка |
| `POST` | `/api/parent/children/{id}/password` | задать ребёнку новый пароль |
| `GET` | `/api/parent/children/{id}/progress` | прогресс своего ребёнка |
| `DELETE` | `/api/parent/children/{id}` | удалить профиль, с паролем родителя |

Родитель видит и меняет только своих детей. На чужой профиль и на
несуществующий ответ одинаковый — `404`, иначе перебором идентификаторов
можно было бы нащупать чужие семьи.

### Ребёнок занимается

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/auth/child/login` | вход по логину и паролю |
| `GET` | `/api/child/me` | свой профиль и общее число звёзд |
| `GET` | `/api/child/progress` | весь свой прогресс |
| `PUT` | `/api/child/progress` | результат по одному заданию |
| `GET` `POST` | `/api/child/projects` | работы из Мастерской |
| `DELETE` | `/api/child/projects/{id}` | удалить свою работу |
| `POST` | `/api/child/quiz` | ответ теста «Что мне интересно» |
| `GET` `POST` | `/api/child/awards` | награды |

Идентификатор ребёнка в этих адресах не передаётся вообще — сервер работает
только с тем профилем, под которым вошли. Подставить чужой некуда.

### Логин ребёнка

От 3 до 20 знаков: буквы, цифры, точка, дефис, подчёркивание. Пароль — от 4
знаков, и это не опечатка: ребёнок шести лет длинный пароль не запомнит, а
защищает его не длина, а запирание аккаунта после десяти неудачных попыток.

**Русские буквы в логине разрешены.** Логин придумывает родитель, а набирает
первоклассник, и «аня2017» он напечатает увереннее, чем «anya2017».

**Смешивать русские и латинские буквы в одном логине нельзя.** Русская «а» и
латинская «a» на экране неотличимы, так что «аnya» и «anya» выглядели бы
одинаково, оставаясь разными логинами. Ребёнок бы не понял, почему не
входит, а взрослый мог бы завести такую пару нарочно, чтобы выдать себя за
другого.

Логин уникален на всю платформу: других способов опознать ребёнка нет.
Поэтому при создании профиля сервер проверяет занятость и предлагает
свободные варианты.

### Как считается прогресс

Записывается по одному заданию, и **лучший результат побеждает**: прошёл на
две звезды, потом на три — остаётся три; прошёл на три, потом кое-как на
одну — всё равно три. Иначе ребёнок, вернувшийся к пройденному уроку просто
поиграть, терял бы заработанное.

Отношение к уроку, наоборот, всегда берётся последнее: это ответ на вопрос
«как тебе урок?», и свежий честнее давнего.

Отдаётся прогресс в том же виде, в котором всегда лежал в браузере — ключ
«курс-задание», как `lessonKey` на странице. Перекладывать данные из одного
вида в другой странице не придётся, а значит и ошибаться при перекладывании.

### Сессия ребёнка

Двенадцать часов, и она **не продлевается** при работе, в отличие от
взрослой. За школьным компьютером через урок сядет другой ребёнок, и чужой
аккаунт не должен остаться открытым. На учебный день двенадцати часов
хватает с запасом.

## Бэкапы

В базе лежат имена детей. Потерять её нельзя, и утечь она тоже не должна.

```bash
sudo install -d -m 700 /var/backups/soberikod
sudo -u postgres pg_dump soberikod | gzip > /var/backups/soberikod/$(date +%F).sql.gz
```

Поставить это в расписание, хранить копии ограниченный срок и — обязательно —
один раз восстановиться из бэкапа на пустой базе. Бэкап, из которого ни разу не
восстанавливались, существует только на бумаге.

Копию стоит держать не только на этом же VPS: диск умирает вместе со всем,
что на нём лежит.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `SOBERIKOD_DATABASE_URL` | локальная база `soberikod` | подключение к PostgreSQL |
| `SOBERIKOD_SITE_ORIGIN` | `https://xn--90agcmkuenf.xn--p1ai` | адрес для ссылок в письмах |
| `SOBERIKOD_CORS_ORIGINS` | пусто | чужие домены, которым разрешены запросы; на сервере не нужно |
| `SOBERIKOD_COOKIE_SECURE` | `true` | `false` только для проверки без HTTPS |
| `SOBERIKOD_SESSION_DAYS_ADULT` | `30` | срок сессии взрослого |
| `SOBERIKOD_SESSION_HOURS_CHILD` | `12` | срок сессии ребёнка |
| `SOBERIKOD_SMTP_HOST` и далее | пусто | почта для подтверждения адреса и сброса пароля |

Без настроенной почты сервер работает, но забытый пароль взрослого придётся
сбрасывать руками в базе.

## Что сервер знает о детях

Имя (то, которое ввёл родитель или сам ребёнок при входе на занятие), логин,
звёзды, реакции на уроки и сохранённые работы. Ни адреса, ни телефона, ни даты
рождения — они не нужны, а значит и храниться не должны.

Пароли не хранятся вовсе: в базе лежат только хеши Argon2id. Токены сессий —
тоже только отпечатки. Из украденной базы нельзя ни войти, ни узнать пароль.

Данные ребёнка без аккаунта, зашедшего на занятие по коду, живут только пока
живёт занятие: родитель его не регистрировал и согласия не давал.

## Проверка на своём компьютере

Нужен локальный PostgreSQL. Дальше:

```bash
cd server
python -m venv .venv
.venv/Scripts/activate          # Linux и macOS: source .venv/bin/activate
pip install -r requirements.txt
set SOBERIKOD_DATABASE_URL=postgresql+psycopg://postgres:ПАРОЛЬ@localhost:5432/soberikod
set SOBERIKOD_COOKIE_SECURE=false
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

Проверка: <http://localhost:8000/api/health> → `{"ok":true}`
