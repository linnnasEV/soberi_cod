# Публикация

Сайт раздаёт GitHub Pages прямо из ветки `main`. Ни сборки, ни внешнего хостинга,
ни секретов в репозитории: пуш в `main` — и через минуту-две изменения на сайте.

**Адрес: https://linnnasev.github.io/soberi_cod/**

```bash
git push origin main
```

## Как это настроено

Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`.
Публикует штатный процесс GitHub «pages build and deployment» — его видно во вкладке
Actions, своего workflow для этого не нужно.

## Проверить, что всё дошло

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://linnnasev.github.io/soberi_cod/
```

Дальше открыть сайт и пройти один урок: если страница открылась, а блоки не
перетаскиваются — скорее всего, не доехал какой-то файл из `js/`.

## Если изменения не видны

Платформа работает офлайн, поэтому браузер отдаёт её из кэша сервис-воркера.
Это не поломка, а ровно то поведение, которое нужно школам со слабым интернетом.

- Обновить страницу с Ctrl+Shift+R (на macOS Cmd+Shift+R).
- Проверить, что в `sw.js` поднята версия `CACHE`: без этого старый кэш живёт дальше.
- Если добавлен новый файл в `js/`, он должен быть в списке `FILES` в `sw.js`,
  иначе офлайн-режим его не увидит.

## Свой домен (потом)

Settings → Pages → Custom domain: домен в зоне `.ru` стоит ~200–300 ₽ в год, запись
CNAME ставится на `linnnasev.github.io`, сертификат GitHub выпускает сам. Делать это
стоит, когда адрес пойдёт в методички и на раздатки, — пока хватает адреса Pages.

## Сервер синхронизации

Pages раздаёт только статику, Python на нём не запустить, и это нормально: сервер
из папки `server/` нужен не всем школам и ставится отдельно, на любой машине с
Python, обязательно под HTTPS — в нём лежат имена детей. Инструкция:
[`server/README.md`](server/README.md).

После публикации сервера впишите его адрес в константу `SYNC_SERVER` в
[`js/sync.js`](js/sync.js) и задайте серверу `SOBERIKOD_ORIGINS` с адресом сайта —
тогда учителю не придётся вводить адрес руками, а чужие сайты к серверу не обратятся.
