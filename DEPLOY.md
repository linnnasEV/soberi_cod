# Публикация

Сайт и сервер живут на своём VPS, на одном домене: **https://соберикод.рф**

Один домен — не удобство, а требование безопасности. Только когда сайт и API
отвечают с одного адреса, вход можно держать в cookie с флагом `httpOnly`,
которую не достанет ни один скрипт на странице. Раздавали бы сайт отдельно —
ключ входа пришлось бы хранить в localStorage, откуда его уводит любая дырка
в вёрстке.

## Как обновить

```bash
git push origin main
```

Затем на сервере:

```bash
sudo bash /srv/soberikod/deploy/deploy.sh
```

Скрипт забирает код, доводит базу до текущей схемы, раскладывает сайт в
`/var/www/soberikod` и перезапускает сервер. В конце сам проверяет
`/api/health` — если напечатал `Готово.`, значит всё поднялось.

Наружу уезжает только список публичных файлов: `index.html`, `sw.js`,
`manifest.json`, `icon.svg`, `css/`, `js/`. Папка `server/`, история git и
инструкции остаются в репозитории — иначе код сервера скачивался бы по прямой
ссылке.

## Проверить, что всё дошло

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://xn--90agcmkuenf.xn--p1ai/
```

```bash
curl -s https://xn--90agcmkuenf.xn--p1ai/api/health
```

Первая команда должна ответить `200`, вторая — `{"ok":true}`. `xn--90agcmkuenf.xn--p1ai`
это соберикод.рф в ASCII-виде: кириллицу в адресе понимает браузер, но не всегда
консольные программы.

Дальше открыть сайт и пройти один урок: если страница открылась, а блоки не
перетаскиваются — скорее всего, не доехал какой-то файл из `js/`.

## Если изменения не видны

Платформа работает офлайн, поэтому браузер отдаёт её из кэша сервис-воркера.
Это не поломка, а ровно то поведение, которое нужно школам со слабым интернетом.

- Обновить страницу с Ctrl+Shift+R (на macOS Cmd+Shift+R).
- Проверить, что в `sw.js` поднята версия `CACHE`: без этого старый кэш живёт дальше.
- Проверить, что поднят `?v=NN` у изменённого файла в `index.html`. Это
  обязательная часть любой правки во фронтенде: nginx кэширует `js/` и `css/`
  на месяц, и без новой версии в адресе до детей доедет старый файл.
- Если добавлен новый файл в `js/`, он должен быть в списке `FILES` в `sw.js`,
  иначе офлайн-режим его не увидит.

## GitHub Pages

Старый адрес `linnnasev.github.io/soberi_cod` продолжает публиковаться из ветки
`main`, пока в настройках репозитория включён Pages. Эту копию стоит отключить:
сервера у неё нет, поэтому кнопка «Войти» там будет честно нажиматься и
бессмысленно ошибаться, а объяснять родителям, какой из двух адресов настоящий,
занятие неблагодарное.

Settings → Pages → Source: **None**.

Репозиторий при этом не меняется, и вернуть всё назад — вопрос одного
переключателя.
